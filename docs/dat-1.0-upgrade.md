# DAT 1.0 upgrade

DAT 1.0.0 shipped on September 24, 2026 for Android and iOS. Voice invocation is included on **both platforms**, alongside Inputs, Motion, Speech, standalone high-quality Photo capture, and camera-stream Audio. All six are **experimental**: Meta permits development/testing, but currently says apps using experimental features cannot be published. Existing registration, device sessions, camera streaming and Display remain available. [Android release notes](https://github.com/facebook/meta-wearables-dat-android/blob/d3159f738676221181577dd745d83d10b6ab46ba/CHANGELOG.md#100---2026-09-24), [iOS release notes](https://github.com/facebook/meta-wearables-dat-ios/blob/1.0.0/CHANGELOG.md#100---2026-09-24).

## Voice invocation

Voice listening belongs to Wearables/the app, **not a `DeviceSession` capability**. The initial supported invocation is `LaunchApp`. Configure capability approval and the spoken app name in Wearables Developer Center; voice listening itself does not require camera or microphone permission. Android separately identifies voice-triggered activity launches with `isVoiceInvocationsIntent`, handled on initial launch and new intents. [Official integration guidance](https://github.com/facebook/meta-wearables-dat-android/blob/d3159f738676221181577dd745d83d10b6ab46ba/AGENTS.md#voice-invocations).

Use `startVoiceInvocations(deviceId)` after registration, listen for `onVoiceInvocation`, and call `respondToVoiceInvocation(invocationId, success, actionOutput?)` **exactly once**, promptly. Its boolean reports whether the response delivered. `getPendingVoiceInvocations()` recovers invocations received before a JS listener attached. Stop listening with `stopVoiceInvocations()`; unanswered requests receive failure during cleanup. If the channel fails, handle `onVoiceInvocationError` and explicitly stop/restart it. Meta AI waits for the response handle, not merely for the app to appear onscreen. [Official Android voice sample](https://github.com/facebook/meta-wearables-dat-android/blob/d3159f738676221181577dd745d83d10b6ab46ba/samples/BirdSpotter/app/src/main/java/com/meta/pixelandtexel/birdspotter/data/dat/DatGlassesVoiceRepository.kt), [shipped iOS voice API](https://github.com/facebook/meta-wearables-dat-ios/blob/1.0.0/MWDATCore.xcframework/ios-arm64/MWDATCore.framework/Modules/MWDATCore.swiftmodule/arm64-apple-ios.swiftinterface).

## Feature coverage

| Feature          | Expo API / event                                                                                        | Required setup                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Inputs           | `addInputsToSession`, `onInputEvent`                                                                    | Started session; approved capability; no runtime permission         |
| Motion           | `addMotionToSession`, `startMotion`, `stopMotion`, `onMotionSample`                                     | Started session; optional 5/10/15/24/30/60 Hz; nullable sensors     |
| Speech           | `addSpeechToSession`, `startSpeech`, `stopSpeech`, `onTranscription`, `onSpeechLocaleChange`            | Started session; DAT `microphone` permission                        |
| Standalone Photo | `startPhotoCapture`, `captureHighQualityPhoto`, `onHighQualityPhotoCaptured`, `onPhotoTransferProgress` | DAT `camera` permission; stop video first; wait for Photo `started` |
| Stream Audio     | `StreamConfiguration.audioCodec`, `onAudioFrame`                                                        | DAT `camera` and `microphone` permissions                           |
| Voice            | `startVoiceInvocations`, `respondToVoiceInvocation`                                                     | Registration and Developer Center voice configuration               |

The session wrappers attach and start Motion/Speech; separate start/stop methods support reuse until session termination. Each capability exposes state/error events and a removal method. For Photo-only use, attach Camera with `startStream: false`; standalone Photo and video compete for camera access. Stop Photo before restarting video. [Official capability lifecycle/permission guidance](https://github.com/facebook/meta-wearables-dat-android/blob/d3159f738676221181577dd745d83d10b6ab46ba/AGENTS.md#inputs).

## Migration and platform differences

- Device state moves onto `Device`: battery, charging, don, hinge and thermal state. Android removes `Wearables.getDeviceState`; iOS removes `deviceStateStream(for:)`. The bridge retains `onDeviceStateChange` and adds state fields to device snapshots plus `getSessionDevice`.
- Meta AI-initiated registration now supplies request objects. Use `onRegistrationRequest`, recover pending requests with `getPendingRegistrationRequests`, and accept/cancel with `respondToRegistrationRequest`.
- Display buttons accept `actionRole: "primary"`; the first primary action gets initial focus. New session errors include terminal `insufficientSDKVersion` and nonblocking `dwaOutOfStuRange`.
- iOS Stream errors now use `thermalHot`, `peakPowerLimit`, `batteryLow`, plus `audioStreamingError`; old thermal/power/battery names are retained only as legacy TS compatibility types. iOS battery can be null; Android uses -1 for unavailable. Android Motion can report `paused`; iOS's shipped Motion enum has four start/stop states.

[Android migration notes](https://github.com/facebook/meta-wearables-dat-android/blob/d3159f738676221181577dd745d83d10b6ab46ba/CHANGELOG.md#100---2026-09-24), [iOS migration notes](https://github.com/facebook/meta-wearables-dat-ios/blob/1.0.0/CHANGELOG.md#100---2026-09-24), [iOS Motion interface](https://github.com/facebook/meta-wearables-dat-ios/blob/1.0.0/MWDATMotion.xcframework/ios-arm64/MWDATMotion.framework/Modules/MWDATMotion.swiftmodule/arm64-apple-ios.swiftinterface).

Audio frames expose base64 PCM bytes, format/interleaving, sample rate, channels, and presentation time. iOS uses its `AVAudioPCMBuffer` format; the Android bridge labels its PCM Int16/interleaved. Preserve these fields when decoding; the byte layouts differ. The SDK exposes iOS `AudioFrame.pcmBuffer` and Android `AudioFrame.buffer`/`presentationTimeUs`. [iOS Camera interface](https://github.com/facebook/meta-wearables-dat-ios/blob/1.0.0/MWDATCamera.xcframework/ios-arm64/MWDATCamera.framework/Modules/MWDATCamera.swiftmodule/arm64-apple-ios.swiftinterface), [published Android Camera 1.0 artifact](https://repo1.maven.org/maven2/com/meta/wearable/mwdat-camera/1.0.0/mwdat-camera-1.0.0.aar).

## MockDeviceKit

Debug builds can pair `metaRayBanDisplay`, preview it through `EMWDATStreamView`'s `mockDisplayDeviceId`, and inject clicks, input, motion feeds, transcription/locale/errors, voice launches/malformed actions, standalone photos/failures, and device health through `mockDeviceSimulate`. Subscribe before injecting; wait for capability readiness. `startMockDeviceTestServer`/`stopMockDeviceTestServer` expose the SDK server; registration outcome injection is Android-only. iOS also ships `MWDATMockDeviceTestClient` for a separate native UI-test process, rather than application JS. Its async disable/unpair overloads permit deterministic teardown. [iOS MockDevice interface](https://github.com/facebook/meta-wearables-dat-ios/blob/1.0.0/MWDATMockDevice.xcframework/ios-arm64/MWDATMockDevice.framework/Modules/MWDATMockDevice.swiftmodule/arm64-apple-ios.swiftinterface), [iOS test-client interface](https://github.com/facebook/meta-wearables-dat-ios/blob/1.0.0/MWDATMockDeviceTestClient.xcframework/ios-arm64/MWDATMockDeviceTestClient.framework/Modules/MWDATMockDeviceTestClient.swiftmodule/arm64-apple-ios.swiftinterface).

Injected mock speech needs no phone microphone; live phone ASR requires host microphone setup (`RECORD_AUDIO` on Android). Mock tests do not establish real-device voice approval, Meta AI routing, background behavior, or deterministic PCM delivery. Verify those with supported hardware. [Official testing guidance](https://github.com/facebook/meta-wearables-dat-android/blob/d3159f738676221181577dd745d83d10b6ab46ba/AGENTS.md#speech).

## React Native integration fixes

DAT Core 1.0 depends on Fresco `fbcore` 3.7.0, while React Native 0.81.5 requests the Fresco family at 3.6.0. A mixed graph builds but crashes during Fresco initialization (`NoOpDiskTrimmableRegistry.getInstance` missing). The Android module uses Gradle's virtual-platform alignment to keep the Fresco family at the highest requested version. This permits newer React Native versions to select their newer Fresco release rather than forcing a downgrade. [DAT Core POM](https://repo1.maven.org/maven2/com/meta/wearable/mwdat-core/1.0.0/mwdat-core-1.0.0.pom), [React Native 0.81.5 versions](https://github.com/facebook/react-native/blob/v0.81.5/packages/react-native/gradle/libs.versions.toml), [Gradle version alignment](https://docs.gradle.org/current/userguide/how_to_align_dependency_versions.html).

CocoaPods can reuse the Pods project UUID when React Native adds the seven SPM products after target UUID stabilization. The Expo plugin enables deterministic UUIDs after `prepare_react_native_project!`, preserving other installation options. Incremental prebuild updates the existing embedding phase for all seven frameworks. These migrations have regression checks in `src/__tests__/plugin.test.js`.

The iOS example builds with all seven frameworks. In the local unsigned iOS 26.0 simulator run, DAT `Wearables.configure()` returned `internalError`, blocking the native smoke check before any capability could start. Mock enabling now propagates initialization failures instead of accessing an uninitialized SDK. Simulator build success does not establish runtime capability delivery; repeat the example check on a configured phone. A prior SDK simulator-bootstrap report describes a similar failure, but its cause/version may differ: [upstream issue 197](https://github.com/facebook/meta-wearables-dat-ios/issues/197).

## Local validation

Package validation passed: 108 Jest tests, TypeScript checks for the package and example, lint, and package/plugin builds. The three prebuild migration checks also failed against the old plugin, establishing that they protect the upgrade behavior. Full Android debug and iOS simulator example builds passed, including all seven DAT modules/frameworks.

The Android emulator passed the example’s real-SDK MockDeviceKit smoke check: session/capability readiness, Inputs, Speech, battery state, duplicate attachment rejection, voice event delivery and pending-request recovery, successful response acknowledgment, duplicate response rejection, and removal of answered requests. The check uses a bounded wait and tears down its mock session/device. This covers those bridge paths; Motion, Photo, Display preview and live Audio still need runtime verification, and real-glasses voice requires Developer Center configuration. The iOS simulator initialization limitation above prevented its runtime check.
